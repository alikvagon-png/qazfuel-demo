# Точечная проверка надёжности перед запуском

- Webhook: незавершённые update_id имеют lease 5 минут; успешный результат отмечается после обработки. Ошибка освобождает claim для повторной доставки, параллельный обработчик получает 503, завершённый дубль пропускается. Старые записи считаются завершёнными. Переход статуса идемпотентен.
- Заявки: при включённом реальном приёме и отсутствии готовой Telegram-привязки режим unavailable, POST отклоняется 503. Нет автоматической подмены реального заказа тестом. Тестовое создание требует явного серверного ALLOW_TEST_ACTIONS=true; simulate дополнительно требует подтверждённого менеджера и server_test. На рабочем сервисе этот флаг не включать.
- Обе очереди уведомлений продолжают попытки после пяти ошибок, с паузой 6 часов (ранние попытки через 5 минут), структурированным логом без контактов и секретов. Бронь с истёкшим сроком менеджеру не отправляется.
- Росстат: данные старше существующего порога 21 день недоступны для новых расчётов, цена/сумма null. Последняя достоверная таблица остаётся в БД; прежние снимки заявок неизменны. Автоимпорт и скидка 300 копеек сохранены.
- Клиент отображает недоступность приёма и не входит в учебную сессию при сбое серверной конфигурации.

Проверки: server/test/critical-reliability.test.js (реальные SQL/HTTP с PGlite, локальный Telegram mock), существующие ACL, HMAC, цены, переходы, закрытые точки и история. Никаких реальных заказов, сообщений менеджеру или destructive-проверок на опубликованной инфраструктуре.

Ограничения: доставка Telegram имеет семантику at-least-once: сбой после принятия сообщения Telegram, но до фиксации БД может дать повторное сообщение; Bot API не предоставляет ключ идемпотентности sendMessage. Claim восстанавливается после lease при аварийном завершении процесса. Бесплатный Render спит, поэтому фоновые повторы/обновления не имеют гарантированного времени. Старые подтверждённые статусы клиентских сообщений при длительном offline могут прийти с задержкой, актуальный статус доступен в приложении. Физические аккаунты Telegram/iPhone и реальные уведомления в этом аудите не тестируются.
